# ACT 模型推理开发纪要 — SG2002 256MB 适配

日期：2026-05-25 至 2026-05-26

## 目标

在荔枝派 SG2002（RISC-V C906, 256MB DRAM）上运行 ACT（Action Chunking Transformer）模型推理。

- 模型：ResNet18 骨干 + 4 层 Transformer Encoder + 4 层 Transformer Decoder + CVAE
- 输入：图像 (1, 3, 224, 224) + 状态 (1, 2)
- 输出：动作序列 (1, 8, 2)
- 参数量：50.7M，FP32 约 193MB

## 分支策略

以 `origin/dev`（最新板级支持，含 LicheeRV Nano SG2002 完整 BSP）为基线，择取 `system_capability_57` 分支的推理相关提交，抛弃其 SG2002/SDHCI/MBR 重复提交（dev 已有等价支持）。

```
dev-inference  = dev（板级支持）+ sys57（推理能力）
```

合并方式：cherry-pick 7 个推理提交 → 新建 `dev-inference` 分支，解决 .gitignore 冲突。

## 阶段一：ONNX 导出与 ncnn 转换

### 1.1 PyTorch → ONNX

- `final_model.pt` (194MB) → `act_model.onnx` (194MB)
- 使用 `torch.onnx.export`，opset 14
- 修复 config 中 `temporal_ensembling_weight` → `temporal_ensembling_coeff` 键名不匹配

### 1.2 ONNX → ncnn (PNNX)

- `act_model.onnx` → PNNX → `act_model.ncnn.{param,bin}`
- FP16 模式：`pnnx fp16=1` → 95MB 模型
- FP32 模式：`pnnx fp16=0` → 190MB 模型

## 阶段二：ruapu 崩溃修复

### 问题

ncnn 在 RISC-V 上的 `ruapu` CPU 特性探测通过执行非法指令（`csrr vcsr`、`fadd.hs` 等）来检测硬件能力。Linux 上通过 SIGILL 信号处理捕获。StarryOS 上 SIGILL 直接导致进程崩溃。

### 修复

Patch ncnn 源码 `src/cpu.cpp`：
- 将 RUAPU_IMPLEMENTATION 条件从 `__riscv` 改为 `0`（禁用 RISC-V 上的 ruapu）
- 移除 `ruapu_init()` 和 `ruapu_supports()` 调用
- RISC-V CPU flags（`zfh`, `zvfh`, `xtheadvector`）保持默认值 0

验证：二进制中 ruapu 符号完全消失，`vcsr` (CSR 0x00f) 访问清除。

## 阶段三：分层量化探索

### 3.1 问题分析

ONNX 模型权重分布（193MB FP32）：

| 组件 | FP32 | 占比 |
|------|------|------|
| Conv (ResNet18) | 43.6 MB | 22.5% |
| MatMul (Transformer attention Q/K/V/O) | 101.0 MB | 52.2% |
| Gemm (Linear layers) | 12.1 MB | 6.2% |
| 其他 (LayerNorm/bias/Split) | 36.4 MB | 18.6% |

### 3.2 量化策略对比

| 方案 | 模型大小 | 平均误差(vs FP16) | 结论 |
|------|----------|------------------|------|
| 全 FP16 | 95 MB | 基准 | 256MB OOM |
| 全 INT8 (ACIQ) | 48 MB | 10.04% | 误差太大 |
| 全 INT8 (KL) | 48 MB | 10.70% | 误差太大 |
| ResNet INT8 + Transformer FP16 | **84 MB** | **0.30%** | ✅ 最优 |
| ResNet FP16 + Transformer INT8 | 59 MB | 9.79% | 无改善 |

关键发现：精度瓶颈在 Transformer（Gemm/MHA），不在 ResNet。逐张量激活量化是限制因素。选择性量化是有效折中。

### 3.3 最终方案：INT8-v3

- 只量化 ResNet 卷积层（`convrelu_*`, `conv_*`）
- Transformer 层保持 FP16
- 校准数据：10 组 NPY 格式（图 + 状态），ncnn2table + ncnn2int8 工具链
- 模型：`act_det_int8_v3.{param,bin}` (84MB)

## 阶段四：QEMU 验证

### 4.1 512MB 验证

| 模型 | 推理时间 | 输出 | 状态 |
|------|---------|------|------|
| FP16 | ~15s | 与 x86 逐位一致 | PASS |
| INT8-v3 | ~15s | 与 x86 逐位一致 | PASS |
| INT8-resonly | ~14s | 与 x86 逐位一致 | PASS |

### 4.2 256MB 验证

| 模型 | 大小 | 256MB QEMU | 精度(vs FP32) |
|------|------|-----------|--------------|
| FP16 | 95 MB | OOM | — |
| INT8-resonly | 84 MB | **PASS** | 平均 2.58% |
| INT8-v3 | 84 MB | **PASS** | **平均 0.30%** |

### 4.3 精度交叉验证

**FP32 基线 (x86, 190MB) vs INT8-v3 (QEMU RISC-V, 84MB, 256MB)**

- 测试用例：50 个，确定性 LCG 随机种子 0–49
- 每个用例：16 个输出元素（8 steps × 2 actions）
- 总计：800 个对比点

| 统计量 | 绝对误差 | 相对误差 |
|--------|---------|---------|
| 平均值 | 0.0030 | **0.41%**（中位数） |
| P90 | 0.0066 | 1.59% |
| P95 | 0.0087 | 2.91% |
| P99 | 0.0150 | 9.54% |
| 最大值 | 0.0241 | — |

误差分布：82.2% < 0.005，96.1% < 0.01，100% < 0.025。

架构差异（x86 vs RISC-V FPU 舍入）：2.04e-4（22x 小于量化误差，可忽略）。
