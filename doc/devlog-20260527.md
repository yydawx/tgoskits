# ACT 模型 TPU 推理全局分析 — 精度瓶颈定位

日期：2026-05-27

## 模型架构

ACT 模型由以下组件构成：

- **ResNet18 backbone**：21 个 Conv2D 层，权重 ~44MB（22.5%）
- **StateEncoder**：Linear + GELU + Linear
- **Transformer Encoder ×4**：每层 LayerNorm → MHA → LayerNorm → FFN(GELU)
- **Transformer Decoder ×4**：每层 LayerNorm → SelfAttn → LayerNorm → CrossAttn → LayerNorm → FFN(GELU)
- **CVAE latent**：固定 32 维（推理时用零向量）
- **ActionHead**：Linear → 输出 (1, 8, 2)

输入：images (1, 3, 224, 224) + state (1, 2)

## 运算分布与 TPU 支持情况

| 运算 | 数量 | 权重占比 | TPU 支持方式 |
|------|------|---------|-------------|
| Conv2D | 21 | 22.5% | 原生支持 |
| MatMul (Attention Q/K/V/O) | 84 | 52.2% | 原生支持 |
| LayerNorm | 20 | — | Div → LutBF16 Slope |
| Softmax | 11 | — | Div → LutBF16 Slope |
| GELU | 18 | — | Erf 或近似替代 |
| Add/Mul/Reshape/Permute | 200+ | — | 原生支持 |

TPU 不原生支持的运算（Div、Erf、Exp、Sqrt）通过 LutBF16 查表实现，分两种模式：
- **Slope 模式**：32 段分段线性插值，适合单调函数（LayerNorm 的 1/x、Softmax 的 1/sum）
- **Mantissa 模式**：32 条目尾数查表，通用但精度差（BF16 尾数仅 7 位，32 条目覆盖不足）

## 两条推理路径

```
ACT Model ONNX (194MB FP32)
  ├─ CPU 路径: ncnn INT8 量化 → C906 标量推理
  │    结果: 38s, 0.30% 误差, 84MB 模型, 256MB PASS
  │
  └─ TPU 路径: TPU-MLIR 编译 → cvimodel → cviruntime 推理
       编译: ONNX → MLIR(TOP) → tpuc-opt → MLIR(TPU) → cvimodel
       结果: BF16 量化误差可接受, 但 GELU 近似误差过大
```

## TPU 编译管线与精度分析

### 编译流程

```
ONNX (FP32, 194MB)
  │ model_transform.py
  ▼
MLIR TOP (GELU = Erf 多项式展开)
  │ tpuc-opt --convert-top-to-tpu
  ▼
MLIR TPU (BF16, GELU 被拆解)
  │ address 分配 + codegen
  ▼
cvimodel (96-100MB)
```

原始模型中 GELU 涉及的 Erf 运算被展开为 3 次 Mul + 1 次 Add，最终需要 Div（除以常数），
该 Div 通过 LutBF16 Mantissa（32 条目）实现，精度不足。

### 三种 GELU 替换策略

| 策略 | ONNX 变化 | Mantissa LutBF16 数 | vs FP32 原始模型误差 |
|------|----------|---------------------|-------------------|
| 原始 Erf | 9×Erf + 10×Div | 9（Erf 相关 Div） | 基准（未测试 TPU） |
| Clip+Rational | 9×Clip + 18×Div | 9（Erf 相关 Div 未减少） | max 0.414, mean 0.134 |
| Rational | 18×Div | 9（同上） | 未测试 |
| NoErf (Clip) | 9×Clip + 9×Div | **0**（消除 Mantissa） | max 0.257, mean 0.058 |

关键发现：Clip+Rational 和 Rational 策略**并未减少 Mantissa LutBF16 数量**（仍为 9 个），
只是额外增加了 Div 运算。只有 NoErf 策略彻底消除了 Mantissa 模式的 LutBF16。

## 误差来源分解（NoErf 变体）

以 x86 FP32 ONNX 为基准，NoErf 变体的最大误差 0.257 分解如下：

| 误差来源 | 最大误差 | 占比 | 说明 |
|---------|---------|------|------|
| GELU 近似（Clip 替代） | 0.253 | 98.4% | 单个 GELU 误差 ≈ 0.00007，经 18 层 Transformer 传播后放大 |
| BF16 量化 | 0.005 | 1.6% | Conv/MatMul 权重和激活从 FP32 → BF16 |

对比 Clip+Rational 变体：

| 误差来源 | 最大误差 | 占比 |
|---------|---------|------|
| GELU 近似（Rational 多项式） | 0.404 | 98.3% |
| BF16 量化 | 0.010 | 1.7% |

结论：**误差的 98% 来自 GELU 近似，而非 BF16 量化。** 单层近似精度虽高（0.00007），
但 GELU 在 Transformer 每层 FFN 中都存在，误差逐层累积放大。

## 关键突破：确定性 ONNX 导出 + 原始 Erf GELU

之前所有 TPU 方案（max 1.92）的误差根源并非 GELU 近似或 BF16 量化，而是 **ONNX 导出时 CVAE latent 的随机采样**。
原始导出脚本使用 `torch.randn_like(mu)` 生成 eps，导致每次导出/推理的 latent 不同，PyTorch 和 TPU 参考值不一致。

解决方案：
1. 确定性 ONNX 导出：monkey-patch `_sample_latent` 使 eps=0，z=mu
2. 使用 PyTorch 遗留 C++ 导出器（`dynamo=False`），强制 opset 14（TPU-MLIR 兼容）
3. 使用原始 Erf GELU（不替换），由 TPU-MLIR 自行处理

结果：TPU BF16 x86 模拟 vs PyTorch FP32 = **max 0.0048, mean 0.0030**
- 19 个 LutBF16，全部为 Slope 模式（无 Mantissa 模式）
- 误差纯属 BF16 量化，无 GELU 近似误差
- 编译管线完整走通：ONNX → model_transform.py → tpuc-opt → model_deploy.py → cvimodel

## 后续方向

核心结论：**原始 Erf GELU + 确定性 ONNX 导出** 方案在 x86 TPU 模拟上精度达标（max 0.5% 误差）。
之前的 GELU 替换策略和 CPU fallback 方向都不需要了。
